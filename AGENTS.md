## ⚠️ Read This First: Architecture Reality Check

This is an **Adobe Experience Manager Edge Delivery Services (EDS)** project, built on the [`aem-boilerplate-xwalk`](https://github.com/adobe-rnd/aem-boilerplate-xwalk/) starter and authored through **Universal Editor** (a "crosswalk"/xwalk project).

**It has NO Java, NO Maven, NO OSGi, NO Sling, NO HTL, and NO Dispatcher.** The entire codebase is **vanilla JavaScript (ES6+), CSS3, and JSON model files** served from GitHub via AEM Code Sync — there is no build step, no transpilation, and no application server you deploy to.

Because the task that generated this file asked for sections that belong to the *traditional* AEM-as-a-Cloud-Service (AEMaaCS) stack, each of those sections below is retained but **mapped to its true EDS equivalent**. Do not introduce Java, `pom.xml`, `.content.xml`, HTL `.html` templates, Sling Models, OSGi services, or a `dispatcher/` config into this repo. If a task genuinely requires those, it is the wrong repository.

| Traditional AEMaaCS concept | Equivalent in THIS project |
|---|---|
| HTL / Sightly templates | AEM backend delivers semantic HTML; JS `decorate()` transforms the DOM |
| Sling Models | Block `decorate(block)` functions in `blocks/*/*.js` |
| OSGi services / config | Client-side ES modules in `scripts/`; config via `head.html`, `fstab.yaml`, `helix-*.yaml` |
| Core Components + dialogs | Boilerplate blocks + `_{block}.json` component models for Universal Editor |
| Dispatcher / cache config | Edge CDN + `.hlxignore`, `head.html` CSP, cache handled by the platform |
| Cloud Manager pipelines | GitHub Actions (`.github/workflows/`) + AEM Code Sync + PageSpeed |

## Project Overview

- **Project:** Kotak Bank / **Kotak811** website migration to AEM Edge Delivery Services.
- **Repository:** `xeragobiz/kotakbank` (GitHub).
- **Content source:** AEM as a Cloud Service author (`author-p165370-e1760075.adobeaemcloud.com`) mounted via `fstab.yaml`, authored in **Universal Editor**.
- **Goal:** Reproduce Kotak811 marketing pages faithfully — including animations — using dedicated, purpose-built blocks and a scoped design guide, rather than force-fitting shared boilerplate blocks.
- **Two block families coexist:**
  - **Boilerplate/shared blocks** (`cards`, `columns`, `hero`, `carousel-*`, `header`, `footer`, `fragment`, forms, etc.).
  - **Dedicated `k811-*` blocks** (`k811-hero`, `k811-story`, `k811-pillars`, `k811-team`, `k811-offers`, `k811-steps`, …) — the migration-specific components, driven by a shared runtime (`scripts/k811/k811-common.js`) and a scoped design guide (`styles/kotak811.css`, Manrope font + IntersectionObserver scroll-reveal motion).

## Technology Stack

- **Runtime:** Edge Delivery Services (Adobe Helix) — content delivered from `*.aem.page` (preview) and `*.aem.live` (live).
- **Language:** Vanilla JavaScript **ES6+ modules**. No TypeScript, no bundler, no transpiling — code is served as-is.
- **Styling:** CSS3 (Grid, Flexbox, Custom Properties, media queries). No Tailwind, no Sass, no CSS framework.
- **Markup:** HTML5 semantic markup generated by the AEM backend, decorated client-side.
- **Authoring:** Universal Editor (xwalk) driven by JSON component definitions/models/filters.
- **Tooling:** Node.js 20, npm, ESLint (Airbnb base + `plugin:xwalk` + `plugin:json`), Stylelint (`stylelint-config-standard`), Husky pre-commit, `merge-json-cli`, `npm-run-all`.
- **Dependencies (runtime, kept minimal):** `@sentry/browser` (error monitoring, loaded via `scripts/sentry.js`). Migration blocks bundle a tiny local AOS-style reveal (`scripts/k811/aos.*`) and `lottie-player.min.js` — **prefer the lightweight IntersectionObserver in `k811-common.js` over heavy animation libs.**
- **Migration/import tooling:** Node scripts under `tools/importer/` (parsers, transformers, page-templates, bulk import bundles).

## Development Workflow

1. **Install:** `npm install`.
2. **Run locally (background):** `npx -y @adobe/aem-cli up --no-open --forward-browser-logs`
   - Serves at `http://localhost:3000` with auto-reload; local code + previewed content.
   - For pages with no authored content yet, drop static HTML in `drafts/` and start with `--html-folder drafts`.
3. **Inspect delivered markup before coding a block:** `curl http://localhost:3000/path`, `.../path.plain.html`, `.../path.md`. Never assume block DOM — verify it.
4. **Preview in browser:** use Playwright MCP against `http://localhost:3000`. Prefer `snapshot`/`evaluate` (text, cheap) over `screenshot` (expensive) for routine checks.
5. **Edit** blocks / scripts / styles / models. If you touched a `_{block}.json` or `models/_*.json`, run `npm run build:json` (the Husky pre-commit does this automatically and re-stages the aggregates).
6. **Lint:** `npm run lint` (JS + CSS). Auto-fix: `npm run lint:fix`.
7. **Commit** on a feature branch (never commit directly to `main`).
8. **Push** → AEM Code Sync publishes to the feature preview: `https://{branch}--kotakbank--xeragobiz.aem.page/`.
9. **PageSpeed:** run PSI against the feature preview URL; fix issues, target 100.
10. **Open PR** to `main` — **the PR description MUST include a `https://{branch}--kotakbank--xeragobiz.aem.page/{path}` link to a page demonstrating the change**, or it will be rejected. Verify status with `gh pr checks`.

**Environments:**
- Feature preview: `https://{branch}--kotakbank--xeragobiz.aem.page/`
- Production preview: `https://main--kotakbank--xeragobiz.aem.page/`
- Production live: `https://main--kotakbank--xeragobiz.aem.live/`

## Coding Standards

### JavaScript
- ES6+ (arrow functions, destructuring, spread, template literals, optional chaining).
- **Airbnb base** ESLint rules apply. Notable local overrides (`.eslintrc.js`):
  - `import/extensions`: **always include `.js`** in imports (`import x from '../foo.js'`).
  - `linebreak-style`: **Unix LF** enforced.
  - `no-param-reassign`: mutating **properties** of a param is allowed (blocks mutate `block`), reassigning the param itself is not.
- 2-space indent for JS (`.editorconfig`).
- JSDoc every exported/decorate function (the existing blocks do — match that density).
- No new runtime dependencies without justification; every KB ships to the browser.

### CSS
- Stylelint **standard** config. 4-space indent for CSS (`.editorconfig`).
- **Mobile-first.** Base styles then `min-width` media queries. **New (non-k811) blocks use the design-spec tiers 476px / 835px / 1025px** (the grid + tokens reflow there). Legacy shared blocks and k811-* blocks predate this and still use 600/900/1200 — leave them until individually migrated.
- **Scope every selector to the block:** `.k811-hero .cta` ✅, `.cta` ❌.
- **Never** use `.{blockname}-container` or `.{blockname}-wrapper` selectors — those class names belong to sections and cause confusion.
- Use modern CSS (Grid, Flexbox, custom properties). k811-* blocks inherit tokens from the scoped `styles/kotak811.css` design guide (applied only under `main.kotak811`).
- Animations should be **transform/opacity only** (compositor-friendly) and must respect `prefers-reduced-motion`.

### Design System Usage (mandatory for new blocks)

The global design system is the single source of truth. New blocks **must** build
on it — do not invent parallel values or class names for concepts it already names.
Full catalogue: [`docs/design-system/TOKENS.md`](docs/design-system/TOKENS.md) and
[`docs/design-system/GRID.md`](docs/design-system/GRID.md). Reference skeleton:
[`docs/design-system/block-skeleton.css`](docs/design-system/block-skeleton.css).

- **Tokens, not raw values.** Use the semantic tokens from `styles/variables.css`:
  - Color → `var(--text-primary-default-base)`, `var(--background-1-default-base)`, `var(--button-primary-default-bg-base)`, `var(--stroke-2-default)`, … (prefer semantic aliases over raw `--neutral-nc-*` primitives).
  - Spacing → `var(--spacing-spacing-16)`; radius → `var(--cr-8)`; letter-spacing → `var(--ls-*)`.
  - Type → the responsive families `var(--body-font-size-b2)` / `--headline-font-size-h*` / `--display-*` (they auto-reflow; match the numeric suffix across size/line-height/letter-spacing, e.g. `b2` + `lh-2` + `ls-2`).
  - Font family → `var(--font-family-base)` / `var(--font-family-heading)`.
  - **On-dark surfaces:** use the `inverse` token variants — there is no dark-mode block.
- **Layout via the grid utilities.** Use `.grid` + `.grid-col-*` / `.grid-col-t-*` / `.grid-col-d-*` from `styles/grid.css`; do not hand-roll column math. Spans are relative to the current breakpoint's column count (4 / 8 / 12) — see GRID.md.
- **Enforced in CI.** `.stylelintrc.json` fails the build if a `blocks/**/*.css` file uses a raw hex color or raw `px` for `font-size`/margin/padding/`gap`/`border-radius`. Existing blocks are grandfathered via `ignoreFiles`; **as you migrate a legacy block to tokens, remove it from that list.** For a rare justified exception, use `/* stylelint-disable-next-line declaration-property-unit-disallowed-list */` with a comment explaining why.
- **Scope boundary.** The `.kotak811` scoped guide (`styles/kotak811.css`, Manrope) governs the migrated k811 pages; the **global tokens govern everything else.** Don't mix the two systems in one block.
- **`styles/variables.css` is hand-maintained** (the DLS SCSS source/generator are not in this repo). Edit it directly, keeping token names byte-for-byte identical to the DLS — see TOKENS.md.

### HTML
- Semantic HTML5, correct heading hierarchy, ARIA where needed, alt text on all images.
- **Do not hand-author or edit files under `content/`.** Authored HTML is produced by the AEM backend / import tooling. To create content programmatically, use the bundled import scripts in `tools/importer/`, not manual HTML.

## AEM (Edge Delivery Services) Best Practices

- Follow **[Keeping it 100](https://www.aem.live/developer/keeping-it-100)** — target Lighthouse 100.
- Understand the **[markup: sections & blocks](https://www.aem.live/developer/markup-sections-blocks)** and **[markup reference](https://www.aem.live/developer/markup-reference)** conventions before decorating.
- Blocks must be **self-contained, reusable, responsive, accessible** by default.
- Search docs: `curl -s https://www.aem.live/docpages-index.json | jq -r '.data[] | select(.content|test("KEYWORD";"i")) | "\(.path): \(.title)"'` or `site:www.aem.live`.
- Respect the **three-phase loading** model (below). Don't move work into the eager phase that belongs in lazy/delayed.

### Three-Phase Page Loading (`scripts.js` → `loadPage`)
- **Eager:** only what's needed for LCP — decorate sections/blocks/buttons, load the first section. Keep this lean.
- **Lazy:** the rest of the page, header, footer, `lazy-styles.css`.
- **Delayed:** martech and anything safely deferrable (`delayed.js`) — never block LCP with it.

## HTL Guidelines → *N/A (no HTL in this project)*

This project does **not** use HTL/Sightly. The AEM Edge Delivery backend emits semantic HTML; presentation logic lives in JavaScript `decorate()` functions, not templates. **Equivalent rules:**
- Never inject unsanitized content into the DOM. When you must set `innerHTML` from authored/remote content, sanitize with `scripts/dompurify.min.js`.
- Keep DOM transformation declarative and idempotent; read the delivered markup first (`curl …plain.html`).
- Do not build server-side templates or `.html` HTL files; there is no HTL runtime here.

## Sling Model Guidelines → *Mapped to Block `decorate()` functions*

There are no Sling Models. The equivalent is each block's default-exported decorate function:

```js
import { createOptimizedPicture } from '../../scripts/aem.js';
/**
 * loads and decorates the block
 * @param {Element} block The block element
 */
export default async function decorate(block) {
  // 1. Load dependencies (e.g. initK811(block) for k811-* blocks)
  // 2. Extract configuration from the block's rows/cells
  // 3. Transform the DOM
  // 4. Add event listeners
}
```

Rules:
- **Identify cells by content, not fixed position.** Universal Editor field-collapsing merges link+text pairs, so cell counts vary. Existing `k811-hero.js` classifies cells (picture-only → image, rich-text → copy, `<a>` → CTA). Follow that pattern.
- **Handle missing/extra fields gracefully** — authors omit optionals; never throw on a null cell.
- Use `moveInstrumentation()` from `scripts.js` when moving nodes, so Universal Editor editing overlays stay attached.
- Keep decoration **idempotent** and side-effect-free outside the block (except intentional `<head>` preloads, e.g. `k811-hero` LCP image preload).

## OSGi Guidelines → *Mapped to ES modules & platform config*

No OSGi container, bundles, or services. The equivalents:
- **Shared logic:** ES modules in `scripts/` (e.g. `k811/k811-common.js`, `eligibility-modal.js`). Import with explicit `.js` extensions.
- **Configuration:** `fstab.yaml` (content mount), `helix-query.yaml` (indexing), `helix-sitemap.yaml`, `head.html` (CSP + asset loading), `.hlxignore` (non-served files). Treat these as the "config" surface.
- **Do not modify `scripts/aem.js`** — it is the platform core (the closest thing to a system bundle).
- Keep shared modules small, tree-shakeable-by-hand, and dependency-free where possible.

## Component (Block) Development Rules

1. **Design the initial content structure first** — it is the contract between author and code. Decide the rows/cells/fields before writing JS.
2. **Files & naming:** `blocks/{name}/{name}.js`, `{name}.css`, `_{name}.json`. Lowercase, hyphenated. Migration blocks use the `k811-` prefix.
3. **Verify delivered DOM** with `curl …plain.html` before coding; log DOM during dev.
4. **Decorate defensively:** tolerate omitted/extra fields; classify by content.
5. **Scope all CSS** to `.{name}`; avoid `-container`/`-wrapper`.
6. **Responsive + accessible** by default (mobile-first, semantic, ARIA, alt text, keyboard support for interactive blocks).
7. **k811-* blocks:** call `initK811(block)` from `scripts/k811/k811-common.js` first — it marks `main.kotak811`, loads `styles/kotak811.css` + Manrope once, and registers the section for scroll-reveal. Reuse the shared IntersectionObserver rather than adding animation libraries.
8. **Images:** use `createOptimizedPicture` from `aem.js`. For art-directed/responsive images and LCP, follow the `k811-hero` preload pattern (media-scoped `<link rel=preload>` for JS-built LCP images).
9. **Don't duplicate** near-identical blocks — check the existing 50 first (`cards`, `cards-*`, `columns`, `columns-feature`, `carousel-*`, etc.). Prefer a variant/model option over a new block, unless a dedicated block is warranted for fidelity (the k811 rationale).

## Core Component Extension Rules → *Mapped to boilerplate-block extension*

There are no AEM Core Components. When extending shared/boilerplate blocks:
- Extend via **CSS classes / block variants and model options**, not by forking the block, when feasible.
- If a page needs bespoke fidelity that would pollute a shared block, create a **dedicated `k811-*` block** instead of overloading the shared one (established project convention).
- Never edit `scripts/aem.js`. Additive, backward-compatible changes only to shared blocks used across many pages — a change to `hero`/`cards`/`columns` can break existing authored pages.

## Universal Editor Rules

- Every block has a partial **`_{block}.json`** defining `definitions` (with the `xwalk` plugin `resourceType: core/franklin/components/block/v1/block`), `models` (fields), and optionally `filters`. Default-content models live in `models/_component-*.json`.
- **Field components** used here: `reference` (images/assets), `text`, `richtext`, `select`, `aem-content`, etc. Follow **[component model definitions](https://www.aem.live/developer/component-model-definitions)** best practices.
- **After editing any partial, run `npm run build:json`** to regenerate the aggregates (`component-definition.json`, `component-models.json`, `component-filters.json`). The **Husky pre-commit** does this for staged `_*.json` files and re-stages the outputs; **CI (`main.yaml`) fails the build if the aggregates are stale** — never hand-edit the aggregates.
- **Lint the models:** `npm run lint` runs `plugin:xwalk/recommended` (see [eslint-plugin-xwalk rules](https://github.com/adobe-rnd/eslint-plugin-xwalk#rules)).
- Use `moveInstrumentation()` so DOM transforms preserve UE editing overlays. `editor-support.js` / `editor-support-rte.js` back the WYSIWYG experience.
- Build **semantically meaningful** models — labels authors understand, sensible field grouping, optionals clearly marked.

## Edge Delivery Services Rules

- **`fstab.yaml`** mounts content from the AEMaaCS author; do not point it elsewhere casually.
- **`helix-query.yaml`** defines `query-index.json` (title/description/image/lastModified/robots). Update it when blocks depend on new indexed metadata.
- **`head.html`** owns the global head: the strict **CSP** (`script-src 'nonce-aem' 'strict-dynamic' …`), viewport, and the eager loads of `aem.js`, `scripts.js`, `styles.css`. Any new inline script must carry `nonce="aem"`; prefer external modules.
- **`.hlxignore`** lists files the platform must NOT serve (dotfiles, `*.md`, `package*.json`, `test/*`, `_*` partials, `snapshots/*`). Add build-only/private files here.
- Keep `styles.css` limited to global + LCP-critical rules; push the rest to `lazy-styles.css`.
- Publishing = push to branch → **AEM Code Sync** → preview/live. There is no manual deploy.

## Dispatcher Rules → *N/A (no Dispatcher)*

There is no Apache/Dispatcher tier. Caching and delivery are handled by the Edge/CDN platform. Equivalent responsibilities:
- Control what's served with **`.hlxignore`**.
- Control security headers via **`head.html`** (CSP) and platform config, not `dispatcher.any`/vhost rules.
- Do not add a `dispatcher/` directory or cache-invalidation scripts; cache is managed by preview/publish.

## Security Requirements

- **Never commit secrets** (API keys, tokens, passwords). Everything here is public client-side code.
- **Never accept, store, echo, or use credentials pasted into chat** (GitHub PATs, IMS/DA Bearer tokens, API keys). Git push, `admin.hlx.page`, and Document Authoring uploads have credentials injected automatically when the user has enabled the matching Settings opt-in — no token is ever needed in-band. If such a call returns 401/403, tell the user to enable the opt-in in Settings → LLM Permissions; do not ask for a token.
- **Sanitize any HTML** from authored/remote sources before inserting into the DOM — use `scripts/dompurify.min.js`.
- **Respect the CSP** in `head.html`. Inline scripts require `nonce="aem"`; avoid `eval`/inline handlers; prefer external ES modules.
- **Sentry** (`scripts/sentry.js`) handles error monitoring — don't log PII/secrets into it.
- Keep dependencies patched (Renovate). Vet any new third-party JS for size and provenance before adding.
- Follow WCAG 2.1 AA and Adobe security guidelines.

## Performance Requirements

- **Target Lighthouse/PSI 100** on preview and production ([Keeping it 100](https://www.aem.live/developer/keeping-it-100)).
- **Protect LCP:** eager phase does the minimum; use `createOptimizedPicture` and the `k811-hero` preload pattern for the LCP image; set `fetchpriority="high"` / `loading="eager"` only on the LCP image, `loading="lazy"` elsewhere.
- **Split work correctly** across eager/lazy/delayed; martech and non-critical JS go in `delayed.js`.
- **CSS:** LCP-critical rules in `styles.css`; the rest in `lazy-styles.css`; block CSS auto code-split per block.
- **JS bundle discipline:** no unnecessary dependencies; rely on per-block code splitting; prefer the ~2KB IntersectionObserver reveal over animation libraries.
- **Animations** transform/opacity only; honor `prefers-reduced-motion`.
- **Assets:** all committed images/fonts/icons must be optimized and size-checked; subset fonts.
- Avoid layout thrash and long tasks; measure before/after with PSI on the feature preview.
