# 03 · Markup, CSS & JavaScript

## Semantic HTML
- **Recommendation:** preserve/emit semantic elements — one `<h1>`, unskipped heading hierarchy, `<button>` for actions, `<a>` for navigation, `<ul>/<ol>` for lists, `<table>` with `<th>`/scope, `<nav>`, `<figure>`.
  **Why:** semantics are simultaneously the accessibility tree, the SEO signal, and free browser behavior (keyboard, focus). Decoration often *destroys* semantics (wrapping everything in `<div>`); resisting that is the cheapest a11y+SEO win available. When you must build DOM, build the semantic element, not a styled `<div>`.
- **Recommendation:** sanitize any authored/remote HTML with `scripts/dompurify.min.js` before `innerHTML`.
  **Why:** it's public, CSP-governed client code; unsanitized injection is XSS and a CSP violation.

## CSS
- **Recommendation:** scope every selector to the block — `.k811-hero .cta`, never bare `.cta`.
  **Why:** block CSS is code-split and loaded whenever the block appears on any page; a bare selector leaks styles site-wide and creates cross-block bugs that are painful to trace.
- **Recommendation:** never use `.{block}-container`/`.{block}-wrapper` selectors.
  **Why:** those class names are generated by the platform for *sections*, not blocks; targeting them couples your block to section internals and confuses maintainers.
- **Recommendation:** mobile-first with `min-width` breakpoints (600/900/1200).
  **Why:** mobile is the constrained case and the majority of traffic; starting there and enhancing upward yields less CSS and no desktop-styles-shrunk-down bugs.
- **Recommendation:** use design tokens (custom properties), not magic numbers.
  **Why:** tokens (`--k811-link`, `--k811-content-max`) keep the design system consistent and make rebrands a one-file change; scattered hexes drift.
- **Recommendation:** keep LCP-critical CSS in `styles/styles.css`, the rest in `lazy-styles.css`.
  **Why:** the eager stylesheet is render-blocking for LCP; every non-critical rule there delays first paint.
- **Recommendation:** animate transform/opacity only, gated on `prefers-reduced-motion`.
  **Why:** transform/opacity are compositor-only (no layout/paint) so they're jank-free; animating width/top/left forces layout and causes CLS. Reduced-motion is a WCAG requirement and a vestibular-safety issue.

## JavaScript
- **Recommendation:** ES6+ modules, `.js` extensions on imports, Unix LF, 2-space indent, JSDoc on exports/`decorate`.
  **Why:** the repo's ESLint (Airbnb + import + xwalk) enforces these; consistency makes 50 blocks readable as one codebase, and `.js` extensions are required because there's no bundler resolving them.
- **Recommendation:** no new runtime dependencies without strong justification.
  **Why:** every KB ships to every visitor's browser uncompressed-of-build-step; a "small" date lib can dwarf the whole page's JS. Prefer platform helpers and the ~2KB shared IntersectionObserver over libraries.
- **Recommendation:** never modify `scripts/aem.js`; put shared logic in `scripts/` modules.
  **Why:** `aem.js` is the platform core (see [01](01-architecture-and-runtime.md)); shared modules (like `k811-common.js`) are the sanctioned extension point.
- **Recommendation:** keep decoration side-effect-free outside the block (except intentional `<head>` preloads).
  **Why:** a block reaching out and mutating global state or other blocks makes rendering order-dependent and fragile.

## Validation checklist — markup/css/js
- [ ] Semantic elements + correct heading hierarchy; injected HTML sanitized.
- [ ] All CSS scoped to `.{block}`; no bare/`-container`/`-wrapper`; mobile-first; tokens not magic numbers.
- [ ] Critical vs lazy CSS split correct; animations transform/opacity + reduced-motion.
- [ ] JS: `.js` imports, LF, JSDoc, no unjustified deps; `aem.js` untouched; `npm run lint` passes.
